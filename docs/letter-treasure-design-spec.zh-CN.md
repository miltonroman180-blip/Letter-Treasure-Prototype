# 字母寻宝队 设计文档

## 1. 产品概述
《字母寻宝队》是一款面向 6 岁儿童的键盘字母学习冒险游戏。孩子通过在键盘上按下正确字母，推动角色在海底、森林、太空三个世界中前进、开门、寻宝和救援伙伴。产品目标是让孩子在低挫败、高反馈的游戏节奏中，逐步建立对英文字母和键盘按键位置的熟悉感。

## 2. 目标用户
- **主要用户**：6 岁左右、刚开始接触英语字母和键盘的小朋友。
- **次要用户**：希望根据孩子阶段调整难度的家长。

## 3. 设计目标
- 让孩子觉得自己在冒险，而不是做练习题。
- 用短任务和即时反馈建立持续成就感。
- 同时支持“看字母”和“听字母”两类学习方式。
- 通过可调难度覆盖启蒙、熟悉、进阶三个阶段。
- 保持操作简单，核心输入仅依赖键盘字母键。

## 4. 核心玩法循环
每个任务遵循以下循环：
1. 屏幕展示目标字母，或播放目标字母发音。
2. 孩子在键盘上按下对应字母键。
3. 系统立刻判断输入。
4. 输入正确时，角色执行前进行为并触发奖励反馈。
5. 输入错误时，根据当前模式给出温和反馈或重试机会。
6. 完成当前小任务后进入下一个目标。

## 5. 世界结构
游戏包含三个主题世界，三者共用同一核心玩法，只替换美术表现、奖励物和音效。

### 海底世界
- **主角形象**：小潜水员或海龟探险家。
- **场景元素**：珊瑚、泡泡、水母、贝壳、发光字母鱼。
- **奖励风格**：珍珠、海星、贝壳贴纸。
- **动作反馈**：吐泡泡冲刺、打开贝壳宝箱、拯救小鱼伙伴。

### 森林世界
- **主角形象**：小狐狸探险家或戴叶子帽的小朋友。
- **场景元素**：树屋、树洞、藤蔓、蘑菇桥、小鸟。
- **奖励风格**：果子徽章、羽毛、树叶卡片。
- **动作反馈**：跳过树桩、打开树洞门、帮助动物朋友。

### 太空世界
- **主角形象**：小飞船驾驶员或圆滚滚机器人。
- **场景元素**：星球轨道、流星、宇宙门、漂浮字母晶石。
- **奖励风格**：星星碎片、能量石、机器人零件。
- **动作反馈**：推进器冲刺、点亮能量门、救援外星朋友。

## 6. 关卡结构
每个世界建议包含 5 到 8 个短关卡。每关时长应控制在数分钟内，避免孩子疲劳。

### 推荐关卡类型
- 字母开门：门上显示目标字母，按对才能通过。
- 宝箱挑战：宝箱刻有字母，按对打开获得奖励。
- 听音找字母：系统读出字母发音，孩子按键作答。
- 追光字母：发光字母短暂出现，按对即可捕获。
- 救援任务：帮助被困的小伙伴完成脱困。

### 关卡设计原则
- 单关目标单一，不混入太多说明文字。
- 一个时间点只出现一个主要任务。
- 每个世界前几关应从少量字母开始，逐步扩展范围。

## 7. 学习模式
游戏支持三种学习模式，由家长在设置中选择：
- 看字母模式：屏幕直接展示目标字母。
- 听字母模式：主要通过语音播报目标字母。
- 混合模式：同时出现视觉和语音提示，后续关卡可逐步减少显式提示。

> 混合模式作为默认推荐模式，因为它最适合从启蒙过渡到熟练。

## 8. 难度模式
游戏提供三档难度，供家长依据孩子阶段调整。

### 超温柔模式
- 按错不判失败。
- 可持续提示目标字母。
- 角色仅短暂停顿，并鼓励继续尝试。
- 适合初学儿童建立信心。

### 普通模式
- 按错会扣除少量星星或奖励。
- 当前任务可继续，不做强失败判定。
- 适合已认识部分字母的儿童。

### 小勇士模式
- 提示更少。
- 可出现更快节奏或纯听音任务。
- 按错会失去部分机会，或需要重做当前小任务。
- 适合已基本熟悉键盘字母的儿童。

## 9. 奖励系统
奖励系统分为三层，确保孩子每次操作都能得到反馈，并拥有长期收集目标。

### 即时反馈
- 角色跳跃、冲刺、发光、挥手。
- 清脆可爱的成功音效。
- 屏幕出现简短鼓励语，如“太棒啦”“成功啦”“继续前进”。
- 场景中出现掉落物、烟花、泡泡、星光等视觉反馈。

### 关卡奖励
- 海底：珍珠、贝壳、海星。
- 森林：苹果、羽毛、橡果、花朵。
- 太空：星星碎片、能量块、卫星贴纸。

### 长期目标
- 海底：修好小船。
- 森林：点亮愿望树。
- 太空：组装小飞船。

建议加入图鉴或收藏册，让孩子能够回顾自己收集的物品和伙伴。

## 10. 趣味强化设计
- 连续答对触发惊喜蛋，如彩虹宝箱或隐藏角色。
- 每个世界都可救出一位伙伴，后续陪伴冒险。
- 可解锁帽子、背包、潜水镜、火箭鞋等外观装扮。
- 通关后播放短庆祝动画，加强完成感。

## 11. 界面与交互
### 主界面
- 采用三世界冒险地图作为入口。
- 海底、森林、太空三个区域均为可点击的大插画。
- 减少传统菜单层级，让孩子一眼理解“去哪里玩”。

### 关卡界面
- 主角位于画面中央偏左，强化前进感。
- 目标字母位于顶部中央，尺寸大且醒目。
- 奖励数量位于右上角，信息简洁。
- 帮助按钮用喇叭图标表示“再念一遍”。
- 家长设置入口应隐藏或通过长按进入，避免误触。

### 儿童友好原则
- 字母、按钮、热点区域都要足够大。
- 背景丰富但不能干扰字母识别。
- 文字提示保持极短，尽量依赖图像、颜色和语音。
- 不使用复杂弹窗中断节奏。
- 如果孩子停留时间过长，可用轻提示引导目标方向。

## 12. 家长设置
家长面板至少包含以下选项：
- 学习方式：看字母 / 听字母 / 混合。
- 提示强度：强 / 中 / 弱。
- 字母范围：分段学习或全部字母。
- 失败规则：不失败 / 扣奖励 / 重试任务。
- 键盘显示：只显示大写提示，或显示大小写对应。

## 13. 实现边界
首个原型建议聚焦以下范围：
- 实现一个可玩的最小版本。
- 优先完成一个世界的 3 到 5 个短关卡。
- 完成看字母、听字母、混合三种模式基础切换。
- 完成三档难度的基础差异。
- 完成即时反馈和基础奖励收集。
- 使用占位美术和简单动画即可，不要求首版完整美术资源。

不进入首版原型的内容：
- 复杂剧情演出。
- 大量可收集伙伴和换装内容。
- 完整 3 个世界全部关卡。
- 复杂账号系统或联网功能。

## 14. 验收标准
原型应至少满足以下要求：
- 孩子能在无复杂说明的情况下开始游戏。
- 看见或听见字母后能完成基本按键互动。
- 按对时有明确、愉快的反馈。
- 按错时不会造成明显挫败。
- 家长能切换模式和难度。
- 一个世界的最小流程完整可玩。

## 15. 下一步（实现计划）
为保证原型在 2~4 周内落地，建议按“先可玩、再可教、后可调优”的顺序推进。

### 15.1 原型技术选型
**目标**：快速搭建可运行、可迭代、可跨平台测试的原型工程。  
**建议方案**：
- 引擎：Phaser（Web）或 Unity（PC/WebGL）二选一，优先团队熟悉方案。
- 资源策略：首版全部采用占位图与通用音效，避免美术阻塞开发。
- 数据配置：关卡、字母池、提示强度采用 JSON 配置，不写死在代码中。
- 埋点最小集：记录正确率、平均反应时间、重试次数、关卡完成时间。

**产出物**：
- 技术选型结论文档（1 页内）。
- 可启动工程骨架（含 1 个可进入的测试场景）。

### 15.2 核心输入和判定模块
**目标**：实现“出题—按键—判定—反馈”的最小闭环。  
**开发要点**：
- 监听 A-Z 键输入，忽略非字母键。
- 支持大小写统一判定（`a` 与 `A` 等价）。
- 题目来源支持两类：视觉目标字母、语音播报字母。
- 输出统一判定结果：`correct / incorrect / timeout`。
- 错误输入进入难度规则分支（不失败 / 扣奖励 / 重试）。

**验收点**：
- 连续 20 次随机测试无判定错乱。
- 输入后 150ms 内出现反馈（视觉或音效）。

### 15.3 单世界关卡循环
**目标**：完成一个世界（建议海底）3~5 关的可玩流程。  
**关卡建议结构**：
1. 字母开门（新手引导）
2. 宝箱挑战（稳定输入）
3. 听音找字母（强化听觉）
4. 追光字母（节奏变化）
5. 救援任务（综合小结）

**流程要求**：
- 关内仅一个主目标，失败不弹复杂窗口。
- 关卡结束展示“本关收集 + 鼓励语 + 下一关入口”。
- 世界内有可见进度（如 1/5、2/5）。

### 15.4 模式与难度系统
**目标**：让家长可一键切换学习方式与挑战强度。  
**实现清单**：
- 学习模式：看字母 / 听字母 / 混合。
- 难度模式：超温柔 / 普通 / 小勇士。
- 参数化控制项：
  - 提示持续时长
  - 允许错误次数
  - 奖励扣减比例
  - 目标出现节奏

**建议做法**：
- 用“模式配置表”驱动逻辑，避免大量 if/else 分叉。
- 所有模式切换实时生效，并在 UI 上给出当前状态提示。

### 15.5 基础 UI 和奖励反馈
**目标**：建立儿童可理解的低文字、高反馈界面。  
**最小 UI 集合**：
- 主地图入口（至少显示海底世界可进入）。
- 关卡 HUD：目标字母、奖励计数、喇叭重播按钮。
- 结算面板：本关表现、收集物、继续按钮。

**反馈最小集合**：
- 正确：角色前进 + 亮色特效 + 成功音。
- 错误：轻震动/短停顿 + 温和语音提示。
- 连对奖励：3 连对触发额外星光或掉落物。

### 15.6 儿童体验验证与微调
**目标**：验证“能玩懂、愿意玩、挫败低”。  
**测试建议**：
- 每轮 3~5 名儿童，单次 10~15 分钟观察。
- 记录指标：
  - 首次上手时间（是否 < 60 秒）
  - 关卡完成率
  - 错误后退出率
  - 主动请求“再玩一关”的比例
- 家长访谈：模式切换是否直观、难度是否可感知。

**微调优先级**：
1. 先修“看不懂目标字母/不知道按哪里”的问题。
2. 再修“反馈不明显、成就感不足”的问题。
3. 最后优化节奏和美术表现。

### 15.7 里程碑建议
- **M1（第 1 周）**：技术定稿 + 输入判定闭环跑通。
- **M2（第 2 周）**：单世界 3 关可玩 + 三学习模式可切换。
- **M3（第 3 周）**：三档难度接入 + 奖励系统接入 + 基础结算页。
- **M4（第 4 周）**：儿童体验测试 + 两轮调优 + 原型验收。

## 16. 下一步（立刻执行）
如果团队今天就启动，建议按以下顺序直接执行：

### Day 1：定稿与建仓
- 确认引擎（Phaser 或 Unity）并锁定版本。
- 创建原型仓库基础目录：`scenes/`、`systems/`、`configs/`、`assets-placeholder/`。
- 新建 `game-config.json`，先定义学习模式、难度参数和字母池。

### Day 2：打通最小闭环
- 完成 A-Z 输入监听与大小写统一判定。
- 实现单题流程：出题 → 按键 → 正误反馈 → 下一题。
- 加入“看字母 / 听字母”两种出题方式（混合模式可先简单并行提示）。

### Day 3：做出第一关可玩 Demo
- 搭建海底世界第 1 关（字母开门）。
- 接入基础反馈：正确前进动画、错误温和提示、奖励 +1。
- 增加关卡完成结算页和“再来一关”按钮。

### Day 4-5：扩展到 3 关并接入难度
- 补齐第 2~3 关（宝箱挑战、听音找字母）。
- 接入三档难度参数（超温柔 / 普通 / 小勇士）。
- 完成家长设置最小入口（可切模式与难度）。

### Week 2：内部试玩 + 儿童小测
- 团队内部先测并修复高频问题。
- 组织 3~5 名儿童进行首轮体验观察。
- 根据数据与观察结果调整提示强度、节奏和反馈强度。

### 完成定义（DoD）
满足以下 5 条即可进入下一阶段：
1. 一个世界至少 3 关完整可玩。
2. 三种学习模式可切换并生效。
3. 三档难度可切换并体现差异。
4. 正误反馈稳定，儿童可在无复杂说明下完成关卡。
5. 家长可在 3 步内找到并修改关键设置。
